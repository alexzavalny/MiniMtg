# Как добавлять новую колоду

Эта инструкция описывает полный путь для новой учебной колоды в MiniMtg: от идеи до работающей игры, квадратных иллюстраций и печатного набора. Она написана по опыту добавления чёрной классической колоды «Могила».

## 1. Спроектировать колоду

Новая колода должна быть отдельным уроком магии, а не просто набором сильных карт.

- Выбери один цвет и ясную игровую идею: быстрый урон, рост существ, защита, контроль или жертвы.
- Сохрани классический дух Magic: знакомые существа, заклинания и механики, без лишней сложности в одной стартовой колоде.
- Собери ровно 40 карт. Обычно подходит 16–18 земель, несколько существ каждой стоимости и небольшая пачка заклинаний.
- Для каждой карты пропиши русское и английское имя, короткое русское описание и ключевые слова.
- У каждой карты должен быть стабильный уникальный `id`: он связывает определение карты, арт, тесты, экспорт и печатные материалы.

До реализации составь таблицу: название, количество копий, стоимость, тип, роль в колоде и нужная механика движка.

## 2. Описать карты в `js/cards.js`

Карты и списки колод живут в `js/cards.js`.

1. Добавь землю и карты в `CARD_DEFS`.
2. Добавь объект в `DECKS`; его `id` далее будет использоваться и для арта, и для обложки.
3. Сформируй `cards` из пар `[id, количество]`.
4. Проверь, что сумма копий ровно 40, а каждый `id` существует в `CARD_DEFS`.

У карты должны быть согласованы `name`, `en`, `type`, `cost`, `colors`, сила/выносливость существ, `keywords`, эффекты и текст. Не прячь игровую логику только в тексте: движок читает структурированные поля.

Пример: `black_knight` имеет `keywords: ['firstStrike']` и `protection: ['W']`; `terror` описывает уничтожение через цель `nonBlackCreature`, а не через особый код для одной карты.

## 3. Переиспользовать механику, затем расширять движок

Перед добавлением нового эффекта проверь, нельзя ли выразить карту уже существующими полями. Если механики всё-таки нет, вводи компактный, обобщённый контракт данных, а не проверку по `card.id`.

Для нового эффекта пройди весь путь:

1. Добавь структурированное описание эффекта в данные карты.
2. Реализуй его семантику в `js/engine.js`.
3. Добавь выбор и проверку легальности цели, если она нужна.
4. Учти зоны, урон, состояние карты и state-based actions.
5. Добавь сообщения в историю и переводы (`js/i18n.js`).
6. Научи ИИ разыгрывать карту и выбирать цель (`js/ai.js`).
7. Добавь точный регрессионный тест.

Сейчас уже есть полезные универсальные эффекты: уничтожение, урон, лечение, добор, контрзаклинание, создание существа, усиление, добавление маны, случайный сброс, потеря жизней или жертва, поворот существа с пропуском следующего разворота и предотвращение боевого урона. Для «Могилы» появились `addMana`, `discardRandom`, `payLifeOrSacrifice` и `addCounter`; для «Прилива» — `tap` и `preventCombatDamage`.

### Цели и срабатывающие способности

Любой эффект с целью должен иметь декларативный тип цели и использовать общую проверку легальности. Новые типы добавляй рядом с общими правилами в движке: `nonBlackCreature` означает существо, которое не является чёрным.

Учти оба сценария:

- игрок выбирает цель через интерфейс;
- ИИ выбирает законную цель через `decideTriggerTargets()` или обычную логику розыгрыша.

Для срабатывающих способностей используй очередь триггеров, а не немедленное изменение состояния внутри случайного участка кода. Так игрок видит событие и может выбрать цель. В «Могиле» это нужно для выхода `Nekrataal` на поле и для счётчика `Sengir Vampire` после гибели раненого им существа.

Ключевое слово должно работать в каждом подходящем месте правил. Например, защита от цвета проверяется не только при выборе целью, но и при блокировании и нанесении урона. Ключевые слова `flash` и `hexproof` также должны менять общие правила: первое позволяет разыграть существо при мгновенной скорости, второе запрещает противнику выбирать его целью. Движок не должен зависеть от DOM: правила меняют состояние, интерфейс только его отображает и запрашивает решения.

## 4. Обновить ИИ, журнал и интерфейс

Новая карта готова только если её умеет использовать компьютер.

- В `js/ai.js` добавь приоритеты для эффекта и выбор подходящей цели.
- Если карта производит ману, ИИ должен уметь применить её, чтобы разыграть иначе недоступную карту.
- Для триггеров добавь отдельное решение ИИ, не оставляй игру ждать человека.
- В `js/main.js` различай цели заклинания и цели срабатывающей способности: обязательный триггер нельзя отменить.
- Добавь новые сообщения в `js/i18n.js`; не хардкодь строку журнала в движке.

Важные действия должны быть видны игроку до результата: цель, заклинание ИИ и ключевой триггер должны быть понятны по журналу и панели действия.

## 5. Создать квадратный арт всех уникальных карт

Каждой уникальной карте нужен собственный квадратный artwork, включая базовую землю. Повторные копии используют один файл.

Требования к промпту:

- строгое соотношение 1:1;
- качественный традиционный или живописный fantasy-art;
- без текста, рамок карт, логотипов, водяных знаков и интерфейсных элементов;
- без графического насилия: игра учебная и подходит детям;
- чёткий главный объект, который узнаётся в маленьком квадрате.

Храни исходные изображения в `assets/card-art/<card-id>.jpg`. В режиме `file://` их нужно встраивать как data URI, иначе загрузка может быть недоступна или испортит экспорт. Для чёрной колоды это делает:

```sh
node scripts/embed-black-card-art.cjs
```

Скрипт собирает `assets/black-card-art-data.js`, а файл подключён в `index.html` сразу после общего `assets/card-art-data.js`. Для следующей колоды либо обобщи скрипт, либо создай аналогичный экспортёр и подключи результат до игровых скриптов.

Проверь, что каждый новый `id` в `MTG.ART_DATA` содержит `data:image/...;base64,`. Обнови `scripts/export-card-data.cjs`, чтобы печатный экспорт видел новый файл с артом.

## 6. Сделать обложку именно для колоды

Обложка — отдельная иллюстрация для карточки выбора колоды, не замена артам карт.

Имя файла обязано совпадать с `deck.id`:

```text
assets/deck-covers/<deck.id>.png
```

Интерфейс строит путь как `assets/deck-covers/${d.id}.png`. Поэтому обложка с красивым, но другим названием не появится. Для `id: 'black'` нужен `assets/deck-covers/black.png`; одного `grave.png` недостаточно.

Для обложки выбирай выразительную композицию с главным персонажем или символом колоды. Не помещай надписи внутрь иллюстрации: имя и описание выводит HTML.

После добавления шестой и следующих колод проверь сетку выбора в `style.css`: она должна показать все карточки на широком экране и не создать горизонтальную прокрутку на телефоне.

## 7. Обновить дополнительные материалы

- Обнови `README.md`, если там перечисляется число или состав колод.
- Обнови `CLAUDE.md`, если появился эффект, правило или тест.
- Добавь колоду в `scripts/build_printables.py`: имя PDF, заголовок, список карт и визуальное описание.
- Если экспорт собирает data-файлы вручную, добавь новый файл.
- Проверь все видимые русские тексты: название, описание колоды, журнал и подсказки.

## 8. Проверка перед завершением

```sh
# Точный тест механик новой колоды
node test/<deck>.js

# Все колоды в симуляции
node test/sim.js 150

# Быстрая диагностическая серия матчапов новой колоды
MATCHUP_ONLY=<deck-id> MATCHUP_GAMES=8 node test/matchup.js

# Экспорт и проверка качества диффа
node scripts/export-card-data.cjs
git diff --check
```

Дополнительно проверь программно:

- в колоде ровно 40 карт;
- все ссылки на карты разрешаются;
- для каждого уникального `id` есть artwork;
- data URI действительно присутствуют в сгенерированном файле;
- обложка существует под точным именем `deck.id`.

Симуляция и короткие матчапы ловят зависания и грубые ошибки, но не доказывают баланс. Маленькая серия матчей — только диагностика; для баланса нужны длинные прогоны и ручная игра.

Открой именно экран выбора колоды и сыграй несколько ходов за человека и против ИИ. Узкий мобильный экран проверь отдельно. Если среда не даёт открыть браузер, не заявляй о ручной UI-проверке: зафиксируй ограничение и отдельно сообщи, что проверено автоматически.

## 9. Эталон: «Могила»

Колода `black` — пример полной реализации:

- 40 карт: 17 болот, ранние угрозы, финишер и шесть заклинаний;
- `Carnophage` учит цене жизни или жертвы на поддержании;
- `Black Knight` показывает первый удар и защиту от белого;
- `Hypnotic Specter` — боевой триггер случайного сброса;
- `Nekrataal` — обязательный триггер выхода с целью;
- `Sengir Vampire` — постоянный счётчик после гибели раненого им существа;
- `Terror` уничтожает только нечёрное существо;
- `Dark Ritual` даёт временный запас трёх чёрных ман;
- восемь квадратных артов и отдельная обложка `assets/deck-covers/black.png`.

Описание всегда должно совпадать с реализованными правилами. Например, `Terror` использует `nonBlackCreature`, а не «любое существо».

## Короткое правило качества

Колода готова, когда она одновременно:

1. Состоит из 40 корректно описанных карт.
2. Работает по правилам и не ломает старые колоды.
3. Понятно играется человеком и ИИ.
4. Имеет квадратный арт для каждой уникальной карты и видимую обложку с именем по `deck.id`.
5. Пройдена автоматическими проверками и просмотрена в настоящем интерфейсе, если это доступно.
